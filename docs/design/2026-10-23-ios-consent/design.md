# v1.2.0 공개 전 iOS 광고 동의 경로 보완

사용자는 “보완 후 세 마켓 진행”으로 아래 범위와 테스트 계획을 승인했다. 화면 개편 PR #439는 `511e48e061b6897d917c2f39dbec7c770526b2f0`에 병합됐다. 정식 독립 UI 검수는 아직 시작하지 않았다.

현재 `apps/mobile/mobileAds.ts`는 iOS에서도 `AdsConsent.gatherConsent()`를 호출한다. Info.plist에는 ATT 요청 문구가 없고, iOS 설정에도 광고 개인정보 메뉴가 노출된다. 이는 App Store 스킬의 현재 iOS 기본 정책과 맞지 않는다. 심사 거절 확정으로 단정하지 않으며 기존 앱이 통과한 사실과 구분한다.

승인 변경:

1. iOS는 ATT를 추가하지 않고 UMP 호출과 광고 개인정보 메뉴를 제거한다. 광고의 비개인화 요청은 유지한다. Android UMP와 힌트 보상은 유지한다.
2. 기존 iOS 앱 시작 경로에서 광고 초기화 전에 IABTCF_ 접두사의 이전 동의 값만 지운다. 퍼즐, 힌트, 계정과 다른 설정 값은 보존한다. 새 네이티브 SDK는 추가하지 않는다.
3. iOS Firebase 광고 저장 및 개인화 동의를 거부한다. 사용 통계의 기존 선택을 보존하고, 선택이 없으면 기본 켬과 설정의 끄기 스위치를 제공한다. 같은 제품의 사용 통계 설정은 공통 core 계약으로 정의하고 세 마켓에서 동작을 맞춘다. 광고와 알림 동의를 사용 통계 스위치에 묶지 않는다.
4. 공개 문구, 개인정보 처리방침과 마켓 신고값을 실제 설정과 대조하고 필요한 부분만 갱신한다. 국가와 판매 지역은 확대하지 않는다. 유럽 등의 iOS 광고는 제한 광고가 되어 수익이 낮아질 수 있다.

검증:

- L3 개발 환경 전체 회귀와 독립 기능 및 UX 검수 3회는 그대로다. 아직 회차를 사용하지 않았으므로 최종 후보에서 세 번 실행한다.
- iOS 분기의 UMP 미호출, 비개인화 요청, 통계 켬과 끄기, 기존 선택 복원, Android 동의 유지 및 보상 경계를 실제 앱과 SDK 대체 입력으로 확인한다.
- iOS 초기화 코드는 컴파일과 격리한 UserDefaults의 Foundation 실행으로 지정 접두사만 지우는지 확인한다. 실제 iOS OS 및 제공자 SDK의 실행 성공은 미실행으로 남긴다.
- 추가 기기 사용은 하지 않는다. 테스트 계획의 foundation 조정 사유를 실제 광고 동의 변경에 맞춰 갱신하고, 사용 통계 관련 analytics 항목도 개발 환경으로 검증하는 범위를 명시한다.
- 별도 코드 PR 한 개로 처리한 뒤 화면 개편과 합친 최종 SHA를 고정한다. v1.2.0, 세 마켓과 서비스 공개 범위는 유지한다.

운영과 복구: 통계 선택은 별도 버전 키로 저장하며 퍼즐과 계정 저장은 수정하지 않는다. 저장이나 SDK 적용이 실패하면 화면에 남기고 앱 이벤트를 막는다. 세 마켓의 현재 배포 상태를 읽고 v1.2.0으로 진행하며 국가 확대는 하지 않는다. 문제 발생 시 기존 마켓 버전과 Cloud Run 이미지로 복구한다.

정본: apple-app-store-registration/references/ios-consent-prompts.md. Firebase 설정 키와 consent API는 Google 공식 문서 및 설치된 SDK 타입으로 확인한다.
