# 모바일 입력 편의 개선 후보

- 날짜: 2026-10-23
- 상태: 아이디어 비교. A 타일 보드의 외형 선택은 완료되었고 새 입력 규칙의 선택과 구분한다.
- 범위: 한국어 입력과 추후 해외 언어의 입력, 작은 화면에서의 보드와 단서 전환.
- 보존: 8×8 한 판, 전체 출제 후보, 한 판의 단어 수와 기존 진행, 완료 정책.

## 현재 코드에서 확인한 점

이미 단어 전체를 입력하는 기본 방식과 칸 입력 방식, 이전과 다음 단서 이동이 있다. 단어 전체 입력을 새 기능처럼 제안하지 않는다.

[RN 입력칸](../../../apps/mobile/App.tsx#L3919)은 선택한 단어 ID, 초기화 번호와 힌트 수를 `key`로 사용한다. 이 값이 바뀌면 입력칸을 다시 만든다. `onSubmitEditing`에서 다음 단어로 이동하고 `submitBehavior`는 지정하지 않았다. [React Native 공식 문서](https://reactnative.dev/docs/textinput#submitbehavior)에 따르면 단일 행 입력의 기본 제출 동작은 입력 포커스를 해제한다. 다음 단어로 옮긴 뒤 재생성되는 입력칸과 이 동작이 키보드 재등장이나 포커스 상실을 만드는지 우선 재현할 대상이다. 실제 모바일에서 이 증상이 재현되었다고 단정하지 않는다.

현재는 화면 전체에 `KeyboardAvoidingView`를 적용하며 선택 칸으로 스크롤하는 처리도 있다. 단순히 키보드 회피 처리를 추가하는 것만으로 개선을 입증할 수 없다. 단서와 입력의 위치, 단어 간 이동 때 입력칸 유지 여부를 함께 점검한다.

## 세 후보

| 후보 | 사용자 행동과 화면 | 장점 | 제약과 권고 |
|---|---|---|---|
| 1 단어 집중 입력, 우선 추천 | 판을 보다가 단서를 고르면 선택 단어, 단서와 입력을 크게 표시. 시스템 키보드는 한 번 열어 여러 단어를 이어 입력. 전체 판 보기를 누르면 키보드를 닫고 돌아감 | 익숙한 한글 자판 유지, 작은 칸을 반복해서 누를 필요 감소, 해외 언어에도 같은 흐름 재사용 | 키보드 자체의 높이를 줄이는 안은 아니다. 입력 중 전체 보드를 무리하게 축소하지 않고 선택 단어와 교차 부분을 보여줘야 함 |
| 2 음절 타일 | 고등어의 예라면 고, 등, 어를 포함해 섞인 후보 음절을 아래 두 줄에 놓고 세 번 눌러 답칸을 채움 | 시스템 키보드를 띄우지 않음, 한 손 조작과 A의 타일 외형에 어울림 | 정답을 구성하는 음절을 보여주므로 난이도가 낮아지는 새 입력 규칙. 첫 세 단어의 보조 후보로 비교하며 전면 적용으로 간주하지 않음 |
| 3 게임 전용 자판 | 앱 안에 고정된 자음, 모음 자판과 삭제, 이전, 다음을 배치 | 크기와 동작을 직접 정하고 키보드 등장에 따른 화면 변화를 줄일 수 있음 | 한글 조합, 받침, 겹받침, 삭제, 천지인 등 사용자 습관과 언어별 입력을 다뤄야 함. 이번 우선안으로 권하지 않음 |

음절 타일은 전체 어휘와 퍼즐의 단어 수를 줄이지 않아도 만들 수 있다. 다만 회상해서 쓰는 과제에서 후보를 알아보는 과제로 바뀌므로 난이도와 완료 지표의 의미가 바뀐다. 긴 단어, 같은 음절이 반복되는 단어, 언어별 글자 단위와 후보 생성도 따로 설계해야 한다. 이 변경을 승인된 일반 입력 개선에 묵시적으로 포함하지 않는다.

## 추천 흐름의 구체안

판을 둘러볼 때는 키보드를 자동으로 열지 않는다. 첫 단서를 고르면 다음처럼 입력에 집중한다.

```text
전체 판 보기                   2 / 18

선택한 단어와 교차 부분

11 세로, 등이 푸른 바닷물고기
            [고] [등] [어]

       이전 단서       다음 단서
─────────────────────────────
       사용자가 쓰던 한글 키보드
```

- 같은 입력칸을 유지하고 단어와 값만 바꾼다. 다음 단어로 옮길 때 키보드를 닫고 다시 열거나 답칸을 다시 누르게 하지 않는다.
- 글자 수가 찼다는 이유만으로 한글 조합 도중 다음 단어로 이동하지 않는다. 다음 키나 명시적인 단서 이동 때 마지막 조합 글자까지 반영하고 이동한다. 이미 맞힌 단어를 매번 다시 거치지 않도록 미완료 단서를 우선한다.
- 입력 중에는 선택한 단어를 큰 답칸으로 보여 준다. 이미 채운 교차 글자와 잠긴 정답, 수정 가능한 글자를 구분한다. 작은 보드 칸을 누르지 않고도 단서 선택과 답 수정이 가능해야 한다.
- 이전과 다음은 키보드 바로 위 손가락이 닿는 곳에 둔다. 전체 판 보기는 키보드를 닫고 판을 확인하는 명시적인 행동으로 둔다. 뒤로 가기와 사용자가 직접 닫은 키보드를 강제로 다시 열지 않는다.
- 보드와 단서, 입력칸을 각각 스크롤해야 하는 화면은 피한다. 긴 단서는 자르지 않고 읽을 수 있게 하며, 키보드가 열린 동안에도 현재 답칸과 다음 단서 이동이 가려지지 않게 한다.

[Apple 입력 지침](https://developer.apple.com/design/human-interface-guidelines/virtual-keyboards)은 키보드 위의 관련 조작과 중요한 화면 요소를 함께 배치하는 방법을 설명한다. [Android 입력 지침](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/visibility)도 키보드가 차지한 뒤의 가용 영역과 예기치 않은 닫힘을 주의하도록 안내한다. 실제 RN과 AIT의 적용 방법은 각 adapter에서 확인한다.

## 집중 검수 기준

기존 승인된 L3 개발 환경 회귀 안에서 아래 검수 깊이를 추가한다. 현재는 검수 계획이며 통과 결과가 아니다.

- 첫 단서를 한 번 골라 입력을 시작하고 세 단어를 연속으로 풀 때, 단서 이동 때문에 키보드가 추가로 닫히거나 다시 열리지 않는다.
- 고등어, 닭고기처럼 받침과 겹받침이 있는 단어의 마지막 조합 글자를 입력한 직후 다음, 다른 단서, 힌트와 전체 판 보기를 눌러도 글자를 잃지 않는다.
- 단어 중간 글자 수정, 전체 선택과 덮어쓰기, 붙여넣기, 교차 글자, 잠긴 칸, 잘못된 답, 지우기와 복원 동작을 확인한다.
- 한 손으로 이전, 다음과 전체 판 보기를 누를 수 있고 같은 목적의 입력 버튼을 중복해서 누르지 않는다.
- 작은 화면, 큰 글자, 긴 단서, 키보드 높이 변화와 다시 열기 후에도 입력 위치와 진행이 유지된다.
- 직접 입력의 첫 입력까지 누른 횟수, 단서 이동 때문에 발생한 키보드 재열림, 입력이 사라진 사례를 비교한다. 원문 입력과 키별 기록을 분석 이벤트에 넣지 않는다.

개발 환경에서 입력 이벤트와 화면, 저장을 먼저 검수한다. 실제 OS 키보드와 한글 자판에서만 확인할 필수 항목이 남으면 해당 항목과 기기 범위만 별도 소명하고 승인받는다. 기기 조회나 실행은 아직 하지 않았다.
