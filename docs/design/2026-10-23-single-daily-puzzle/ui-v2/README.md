## 비교와 추천

세 안은 동일한 한국어 8×8, 18단어 예시를 사용한다. 2단어를 채웠고 처음 세 단어 안내의 마지막 단서인 세로 11번 고등어를 선택한 상태다. 난이도 선택을 추가하거나 단어 수를 줄여 외형 차이를 만들지 않았다. 이름은 시안 구분용이며 앱 이름 변경을 뜻하지 않는다.

| 안 | 형태와 분위기 | 풀이 중 우선순위 | 구현 방법과 비용 |
|---|---|---|---|
| A 타일 보드, 추천 | 따뜻한 바탕, 도톰한 타일, 짙은 잉크색 글자, 살구색 선택 | 밝은 판, 선택한 단어, 단서, 입력 순서 | CSS와 RN 도형, 경계와 짧은 그림자 중심. 별도 대형 이미지와 글자 그림 없이 구현 가능 |
| B 별빛 퍼즐 | 밤색 공간, 밝은 조각, 작은 별빛 | 밝은 타일과 단서의 대비 | 작은 별무늬와 배경 그라데이션. 네이티브는 같은 색과 도형을 adapter에서 렌더링. 글자와 보드는 이미지로 굽지 않음 |
| C 데일리 퍼즐북 | 종이, 얇은 격자, 잉크, 벽돌색 강조 | 익숙한 퍼즐 지면과 읽는 편안함 | 단순 격자와 종이 패턴. 자주 바뀌는 장식 에셋 없이 유지 가능 |

A를 추천한다. 한글과 알파벳 모두 읽기 편한 타일 구조를 유지하면서, 눌림과 정답 채움만으로 게임 느낌을 더할 수 있다. B는 분위기가 가장 뚜렷하고 C는 퍼즐북 성격이 강하다. 어느 안도 유지비 감소나 수익 개선을 입증한 것은 아니다.

## 선택 후 공통 외형 규칙

보드가 화면의 중심이다. 홈의 주 행동은 오늘 판 시작 또는 이어 풀기 하나이며 지난 퍼즐과 내 기록은 보조 진입으로 남긴다. 풀이에서는 현재 단서와 입력을 고정하고, 다른 단서는 목록에서 고른다. 긴 안내를 읽어야 보드로 갈 수 있는 흐름은 쓰지 않는다.

타일은 평상시, 선택한 단어, 현재 칸, 정답 채움, 오류와 비활성 상태를 구분한다. 현재 칸은 경계와 밑줄, 정답은 글자와 완료 수로도 구분하여 색만으로 뜻을 전달하지 않는다. 눌림 80~120ms, 정답 채움 160~220ms, 판 완성 시 짧은 표시를 구현 기준으로 삼는다. 움직임 줄이기 설정을 따른다. 현재 HTML에는 색 전환과 눌림만 있으며 완성 연출과 소리는 구현되지 않았다.

꾸미기 재화, 하트, 새 미션과 연속 출석 보상은 추가하지 않는다. 기존 힌트와 광고, 저장, 완주 정책은 승인된 기능 설계를 따른다. 스킨은 AIT/Web과 RN에서 각각 구현하고 판 선택과 진행 정책은 `packages/crossword-core`에서 공유한다.

## 이후 해외 확장을 위한 구조

이번 업데이트는 한국어 콘텐츠와 기존 세 마켓을 유지한다. 영문 화면은 후속 작업의 화면 배치를 확인하는 예시이며 영어판 출시나 외국어 사전 검수 완료를 뜻하지 않는다.

- UI 문구는 실제 텍스트로 표시하고 그림, 버튼 바탕과 분리한다. 긴 버튼, 두 줄 이상의 단서, 숫자와 날짜 형식을 언어별로 확인한다.
- 정답 언어와 UI 언어를 혼동하지 않는다. 퍼즐의 정답, 단서, 출처와 의미 식별자는 언어별 콘텐츠로 관리한다. 기존 한국어 정답을 번역해서 같은 격자에 끼우지 않는다.
- 한글 조합 입력, 알파벳과 악센트, 결합 문자를 고려한다. 이후 언어별 단어 분할은 보이는 글자 단위와 정규화 기준을 정한 후 구현한다. 영문을 한글 음절과 같은 반복 기준으로 검사하지 않는다.
- 국가와 언어를 국기 하나로 표시하지 않는다. 언어 이름을 사용하고, 첫 진입에 국가 선택 화면을 추가하지 않는다.
- 이번 공개 날짜와 생성 시각은 승인된 한국 운영 기준을 따른다. 후속 해외용 발행은 콘텐츠 언어, 지역과 기준 시간대를 정한 뒤 설계한다.
- 전체 어휘와 한 판의 단어 수 보존은 이번 기능의 인수조건이다. 영문 배치 예시는 8×8, 22단어이며 실제 해외 발행용 콘텐츠 팩은 별도 사전 권리, 단서 품질과 생성 안정성 검증이 필요하다.

## 확인한 범위와 남은 검수

HTML 시안을 Edge와 공용 Playwright에서 렌더링했다. 390×844 기준 프레임, 360×800과 430×932 브라우저에서 내부 화면을 각각 확인했다. 작은 브라우저에서는 갤러리 여백 때문에 실제 프레임 너비가 324px, 큰 브라우저에서는 390px다.

세 안의 정답 입력과 진행 수 변경, 단서 목록 선택, 홈으로 이동과 이어 풀기, 영문 소문자 입력을 실행했다. 긴 단서의 줄바꿈과 입력칸, 키보드 그림의 잘림을 점검했다. [시안 확인 결과](preview-check.json)는 제품 실행 결과와 명시적으로 구분한다. 한국어 조합 입력, 실제 OS 키보드 높이와 RN 렌더링은 이 자료에서 검증하지 않았다. 키보드 그림은 배치 예시이며 앱 전용 키보드 구현 요구가 아니다.

제품 구현 후 승인된 L3 개발 환경 전체 회귀와 독립 검수 3회, 세 마켓의 기존 저장과 단일 판 정책을 확인한다. 보드가 작아질 때는 단서 목록에서 충분한 크기로 단어를 선택할 수 있어야 하며, 큰 글자와 실제 키보드로 남는 영역은 구현 때 다시 검수한다. 기기를 사용하거나 기기 검수를 통과한 것으로 기록하지 않는다.

선택할 항목은 A, B, C 중 시각 방향 하나다. 선택 메시지와 이 폴더의 버전을 연결한 뒤 나머지 화면과 상태를 같은 방향으로 구현한다.
