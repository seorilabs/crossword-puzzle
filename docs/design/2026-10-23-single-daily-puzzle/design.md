- 상태: 사람 검토 대기
- 조사 소스: e64931fbff57c3e2690a5bcbfdf45d49f31ade04
- 회귀 비교 기준: 세 마켓 현재 배포 버전을 포함하는 v1.1.10부터 전체 변경 검수
- 요청 근거: 2026-10-23 대화의 큰 판 단일화와 쉬운 어휘, 단어 풀 보존 요구
- 해석: 전체 출제 후보와 한 판의 단어 수를 모두 보존하는 안. 사용자 답변이 다르면 구현 전 갱신한다.
- 관련 시각 자료: preview.html. 실행 화면이 아닌 흐름 검토용 시안이다.

## 목적과 변경 범위

쉬움과 어려움 선택을 없애고 하루 한 판에 집중한다. 현재 큰 판인 8×8을 유지하며 정답 수를 줄여 난이도를 낮추지 않는다. 전체 워드뱅크 24,963단어를 보존하고 익숙한 어휘의 출제 비중, 단서 설명, 첫 입력 안내로 접근 부담을 낮춘다. 새 미니게임, 보상이나 광고 변경, 전면적인 아트 교체는 포함하지 않는다.

| 항목 | 결정 |
|---|---|
| 하루 콘텐츠 | 8×8 한 판. 쉬움과 어려움 선택, 두 단계 사다리 제거 |
| 단어 수 | 최소 18개, 큰 판 기존 수준인 18~22개를 목표. 30일 시뮬레이션에서 평균 단어 수가 기존 큰 판보다 낮으면 발행하지 않음 |
| 전체 후보 | 24,963개 보존. 학습 등급으로 삭제하거나 출제 가능성을 0으로 만들지 않음 |
| 낯선 말 | 낮은 우선순위로 남겨 다양성을 보존. 나오면 일상어 설명과 구체적인 상황 예시를 우선 |
| 첫 실행 | 별도의 작은 입문 판을 거치지 않고 같은 오늘 판으로 진입. 쉬운 단서 3개를 먼저 안내하되 자유 선택과 건너뛰기 허용 |
| 완료 | 모든 단어를 실제로 채워야 완료. 첫 3개를 전체 완주로 기록하지 않음 |

큰 판은 처음 보는 사람에게 더 길고 복잡해 보일 수 있다. 따라서 한 판 단일화만 하고 끝내지 않고, 첫 단서 추천과 단서 설명을 같은 범위에 포함한다.

## 화면과 상태

기존 앱의 서체, 민트 색상, 보드 입력과 결과 화면을 재사용한다. 홈은 오늘 판 미리보기와 시작 또는 이어 풀기 한 가지 주 행동을 둔다. 날짜별 지난 판과 기록은 보조 진입으로 둔다.

첫 실행도 오늘 8×8 판 전체를 보여 준다. 안내는 한 번에 한 단서만 강조하고 입력 칸, 단서, 첫 글자 입력의 관계를 보여 준다. 쉬운 단서 3개는 순수 core 정책으로 선정한다. 안내를 닫아도 입력과 저장이 유지되고 안내 없이 계속 풀 수 있다. 완료 기준이나 무료 힌트 규칙을 줄이거나 바꾸지 않는다.

작은 화면, 큰 글자, 한국어 조합 입력, 키보드 표시 상태, 오프라인, 불러오기 실패, 저장 복원, 완료 후 재진입을 검수한다. 신규 설치와 기존 저장을 격리한 실제 개발 화면을 각각 확인한다.

## 어휘와 생성 정책

전체 후보를 보존하는 가중 무작위 추첨을 core에 둔다. 초급과 중급은 우선하지만 고급과 등급 없음도 양의 가중치를 가져 출제 가능성을 남긴다. 현재처럼 슬롯별 후보를 일부 추첨하되 원본 워드뱅크는 축소하지 않는다. 사전 등급 없음이 곧 어려운 말이라는 가정도 두지 않는다.

실험 초기 가중치는 초급 128, 중급 32, 고급 1, 등급 없음 1이다. 이는 승인 후 운영용 30일 실험에서 검증할 초기값이다. 후보 보드는 기존 교차율, 밀도, 연결성, 정답과 어근의 중복 조건을 모두 통과한 뒤 익숙한 어휘 비율과 최초 추천 단서 가능 여부로 고른다. 양의 가중치와 전체 후보 보존이 인수조건이며, 빈도를 높이려고 반복 제한을 완화하지 않는다.

정답 90일, 어근 14일 중복 제한을 유지한다. 낯선 말의 단서는 정답 의미를 정확히 유지하면서 짧은 일상어와 상황 설명을 제공한다. 생성 후보 모두를 유료 모델로 매번 새로 쓰지 않고 기존 사전과 검수 단서, 확인된 보강 자료를 재사용한다. 원문과 출처, 의미 식별자를 유지하고 동음이의어를 다른 뜻으로 섞지 않는다. 모호한 단서는 검수 보강 대상으로 기록한다.

설계 탐색에서는 전체 풀을 보존하고 8×8, 18단어 이상인 가중 후보에서 초급과 중급 비중 56~72%를 확인했다. 이 탐색은 최근 정답 이력과 모든 품질 검사를 포함하지 않으므로 운영 검증 통과로 세지 않는다.

## 책임, 데이터와 호환성

정책과 판 선택, 최초 추천, 난이도 없는 사용자 문구, telemetry 규약은 packages/crossword-core에서 공유한다. 생성과 공개본 검사는 server/batch에서 수행한다. AIT는 src adapter, Android와 iOS는 apps/mobile adapter가 기존 저장과 입력을 이어 사용한다.

옛 easy와 hard 퍼즐, 진행 상태와 완료 기록은 유지한다. 새 화면은 오늘 판 한 개만 권하지만 과거 두 판을 읽을 수 있어야 한다. 구버전 데이터가 실제로 존재하므로 그 해석 경로를 죽은 코드로 보고 삭제하지 않는다. 새 후보의 정책과 옛 데이터 해석을 구분하고 불필요한 새로운 호환 계층은 만들지 않는다.

새 판의 전송 데이터는 기존 큰 판과 같은 difficulty=hard, 날짜별 h01 슬롯과 YYMMDD01 식별자를 유지한다. 이는 이미 배포한 앱이 읽는 데이터 필드이며 새 사용자 화면의 난이도 구분으로 쓰지 않는다. 현재 buildDailyLadder는 없는 easy를 건너뛰고 hard 한 판을 표시하며 getDailyFreePuzzleSummary는 공개 시각을 지난 당일 판을 선택한다. 이 실제 경로를 구버전 fixture 테스트로 고정한다. 새 클라이언트를 먼저 배포한 뒤 다음 날짜부터 생성과 health를 단일 hard 판 정책으로 맞춘다. 이미 진행 중인 퍼즐 ID와 답을 덮어쓰지 않는다.

별도 작은 입문 퍼즐 경로와 두 단계 선택 코드는 실제 과거 저장 조회에 필요한 부분만 남기고 대체된 신규 흐름은 제거한다.

## 생성 시점과 운영

단일 판 전환이 완료되면 다음 날 팩을 전날 23:00에 생성해 자정 지연을 줄인다. publishedAt은 해당 날짜 00:00 KST로 둔다. 원격 manifest의 미래 판을 자정 전에 노출하지 않는지 세 마켓의 선택 규칙으로 확인한다. 생성 후 공개본을 해당 날짜로 즉시 검사하고 자정 뒤 최종 점검도 둔다. 오늘과 다음 날을 잘못 계산하거나 재실행이 기존 퍼즐을 교체하면 실패다.

TDD: 가중 추첨의 전체 후보 보존과 재현성, 일간 단일 판 선택, 과거 저장 복원, 최초 3단서 선정, 자정 경계와 새 완료 조건을 우선한다. 문구는 실제 입력과 렌더링으로 검수한다.

테스트는 L3, 개발 환경 전체 회귀와 작성자 외 독립 검수 3회다. web과 RN 개발용 경계 대체 구현을 사용해 신규 진입, 입력, 힌트, 광고 보상 경계, 완료, 저장 복원, 오프라인과 오류를 검증한다. npm run check:release-parity, npm run build, npm run check:mobile을 모두 실행한다. 실제 네이티브 SDK나 권한을 바꾸는 작업은 포함하지 않아 기기 사용을 계획하지 않는다. 개발 환경으로 확인할 수 없는 항목이 새로 확인되면 그 항목만 별도 소명한다.

현재 저장소에 중앙 형식의 feature-inventory가 없으므로 먼저 실제 기능을 조사해 등록한다. 검사 틀 부족을 통과로 기록하지 않는다. 변경 경로로 검증 하한이 올라가면 개발 환경 실행을 더하고, 승인 계획의 수준을 임의로 낮추지 않는다.

## 적용, 출시와 되돌리기

승인 뒤 실행 이슈와 PR 흐름을 사용한다. 운영 정리 설계와 제품 변경은 별도 PR로 나눠 먼저 운영비와 알림을 정리한다. 제품 변경은 AIT, Google Play, App Store와 생성 서비스를 같은 정책으로 검증하고 현재 구버전의 실제 읽기 경로까지 확인한 뒤 순차 적용한다.

테스트 계획의 끝 지점은 세 마켓과 서비스 공개다. 이 설계와 test-plan.json 승인 시 그 범위의 공개 적용까지 진행한다. 운영 준비, PR 병합, 빌드, 업로드, 심사, 승인, 공개, 실제 공개본 확인은 구분해 기록한다.

오류 시 기존 배포와 보호한 생성 이미지를 사용한다. 기존 사용자 진행을 삭제하지 않으며 이미 발행한 정답을 다른 답으로 덮어쓰지 않는다. 생성 전환일과 실제 검수 근거가 확정되기 전에는 공개 전환 완료로 표시하지 않는다.
