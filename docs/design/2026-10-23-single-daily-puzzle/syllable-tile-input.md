# 한 판 완성을 돕는 음절 타일 입력

- 날짜: 2026-10-23
- 방향: A 타일 보드의 기본 입력을 전체 판에서 음절 타일 선택으로 바꾼다.
- 사용자 요청: “차라리 음절 타일 선택하는게 어때? 난이도는 낮게 해주고 게임 한판을 잘 완성할 수 있게 해주는거지”
- 상태: 사용자 요청을 반영한 상세 설계. 실제 앱 구현과 검수 완료를 뜻하지 않는다.
- 앞선 비교: [입력 편의 개선 후보](input-usability-options.md). 시스템 키보드 중심의 추천은 이 방향으로 대체한다.

## 목표와 보존

단서를 읽고 생각한 답을 타일로 완성한다. 한글 조합 입력이나 작은 칸 조작 때문에 멈추는 일을 줄이며, 낮은 난이도로 매일 한 판을 끝내는 즐거움을 준다. 첫 세 단어에만 제한하지 않고 오늘 판 전체에서 같은 입력 방식을 사용한다.

기존 8×8 한 판, 전체 출제 후보 24,963개, 판당 최소 18단어와 기존 큰 판 수준의 단어 수 보존 조건을 유지한다. 후보 타일은 현재 단어를 입력하는 도구이며 출제 사전을 줄이는 필터가 아니다. 익숙한 어휘와 읽기 쉬운 단서는 별도로 계속 보완한다.

## 화면과 기본 조작

```text
오늘의 퍼즐                         2 / 18

             8×8 보드

11 세로, 등이 푸른 바닷물고기
             [  ] [  ] [  ]

             [나] [고] [무]
                [어] [등]

       이전 단서   지우기   다음 단서
```

모바일 시스템 키보드를 열지 않는다. 현재 단어를 큰 답칸으로 보여 주고, 타일 한 번 누르기로 선택 칸을 채운다. 드래그, 길게 누르기와 별도의 제출 버튼은 필수 조작으로 두지 않는다. 단서 목록으로도 원하는 단어를 고를 수 있다.

타일은 손가락으로 누르기 충분한 크기를 먼저 확보한다. 최소 높이 56을 목표로 하고, 가로 공간이 부족하면 열 수를 줄여 줄바꿈한다. 타일 수를 맞추려고 글자와 터치 영역을 작게 만들지 않는다. 긴 단어, 큰 글자와 작은 화면에서 단서와 답칸이 계속 보여야 한다.

## 후보 구성과 복구

- 시작값은 정답을 완성하는 데 필요한 음절과 방해 음절 두 개다. 정답 음절은 섞어서 보여 주며, 비슷한 모양이나 발음을 일부러 많이 넣어 함정으로 만들지 않는다. 후보 수는 실제 첫 풀이 검수 결과로 조정한다.
- 반복 음절은 필요한 횟수만큼 별도 타일로 제공한다. 같은 글자의 타일도 각각 식별하여 한번 사용한 조각을 중복 소비하거나 필요한 조각이 사라지지 않게 한다.
- 교차 단어와 기존 힌트로 정답이 확인된 칸은 미리 채워 둔다. 아직 확정되지 않은 기존 입력은 정답 잠금과 구분하여 바꾸거나 지울 수 있게 한다.
- 단어가 모두 채워지면 자동 확인한다. 맞으면 해당 단어를 짧게 강조하고 다음 미완료 단어를 추천한다. 가능하면 교차 글자가 이미 채워진 단어를 우선하여 다음 풀이의 부담을 낮춘다. 첫 세 단어 안내는 기존 쉬운 단서 추천을 먼저 따른다.
- 틀리면 맞는 위치의 음절은 남기고 틀린 위치만 다시 고르게 한다. 사용한 틀린 조각은 후보로 돌려주며, 정답 조각이 모두 소모되어 더 풀 수 없는 상태를 만들지 않는다.
- 답칸을 눌러 수정 위치를 고를 수 있다. 지우기는 최근의 수정 가능한 선택을 취소하며 정답으로 잠긴 칸과 이전 진행을 통째로 지우지 않는다.
- 타일 순서는 단어를 푸는 동안 유지한다. 일반적인 화면 갱신이나 오답 처리만으로 자리를 다시 섞지 않는다. 퍼즐 ID와 단어 ID를 기준으로 재현할 수 있게 하며 저장 복원 후에도 남은 타일과 답칸이 일치해야 한다.

오답 횟수 제한, 목숨과 시간 초과는 추가하지 않는다. 막혔다고 필수 광고를 보거나 처음부터 다시 시작하게 하지 않는다. 기존 무료 힌트와 선택적인 광고 보상 규칙은 유지하며 타일 선택에 별도 비용을 붙이지 않는다.

## 구조와 데이터

후보 구성, 중복 타일 수량, 선택과 취소, 부분 정답 유지, 다음 미완료 단어 추천과 계측 규칙은 `packages/crossword-core`에 둔다. AIT/Web과 Android/iOS는 같은 순수 정책을 각 플랫폼 버튼으로 렌더링한다. 앱의 퍼즐 입력에는 숨겨진 시스템 텍스트 입력칸에 의존하지 않는다. 다른 화면에서 필요한 일반 텍스트 입력까지 제거하지 않는다.

기존 퍼즐, 저장한 글자와 힌트 지갑을 유지한다. 예전 box와 cell 입력 모드는 새 풀이의 기본 선택으로 노출하지 않으며 대체된 입력 전환 UI와 실제 미사용 코드는 구현 때 사용처를 확인해 제거한다. 과거 퍼즐을 읽는 저장 형식과 난이도 필드 해석은 유지한다.

타일 상태는 기존 글자 저장과 확인된 정답 상태에서 재구성할 수 있는지 먼저 검토한다. 재구성으로 충분하면 같은 진행을 별도 형식으로 중복 저장하지 않는다. 복원이 불가능한 정보만 저장 계약의 필요성과 구버전 영향 확인 후 추가한다.

완료는 여전히 모든 단어를 실제로 완성했을 때만 기록한다. 첫 세 단어 안내 완료와 한 판 완료를 구분한다. 새 입력 방식과 정책 버전을 완료 지표의 비교 구간에 남겨, 이전 직접 입력 이용자와 구분한다. 타일별 원문이나 키 입력 로그는 수집하지 않는다.

## 이후 다른 언어

화면의 일반 이름은 타일 또는 글자 고르기로 두고 특정 국가나 자판 이름을 테마로 쓰지 않는다. 한국어는 완성된 한 음절, 이후 알파벳 언어는 해당 언어에서 사용하는 글자 단위를 타일로 다룬다. 정규화와 반복 글자, 악센트와 결합 문자 처리는 언어별 콘텐츠 계약에서 정한다. 해외 정답과 단서를 기존 한국어 퍼즐의 단순 번역으로 만들지 않는다.

## 추가 인수조건

| 조건 | 통과 기준 |
|---|---|
| TILE-1 한 판 전체 | 모든 오늘 퍼즐 단어를 타일만으로 완료할 수 있으며 시스템 키보드를 요구하지 않음 |
| TILE-2 양과 어휘 | 원본 출제 후보와 판당 단어 수 보존 조건을 유지함. 타일 방식 때문에 길거나 반복 음절이 있는 단어를 후보에서 빼지 않음 |
| TILE-3 항상 완성 가능 | 각 단어의 필요한 정답 조각과 반복 개수가 충분함. 오답, 취소와 교차 글자 처리 후에도 정답을 구성할 수 있음 |
| TILE-4 낮은 실패 부담 | 오답에서 맞는 위치는 유지하고 틀린 위치만 다시 고를 수 있음. 진행 초기화, 횟수 제한과 필수 광고 없음 |
| TILE-5 단서 이동과 복원 | 이전, 다음과 직접 선택, 부분 입력 후 재진입, 기존 직접 입력 저장과 힌트 사용 후에도 조각과 답칸이 일치함 |
| TILE-6 손가락 조작 | 작은 화면과 큰 글자에서도 후보와 지우기, 단서 이동을 누를 수 있고 단서와 답칸이 가려지지 않음 |
| TILE-7 완료 정직성 | 안내 완료와 모든 단어 완료를 구분하고 기존 완료 이벤트를 중복 기록하지 않음. 입력 정책 변경 전후를 구분 가능 |

검수 등급과 마켓 끝 지점은 기존 L3 개발 환경 전체 회귀, 독립 검수 3회와 세 마켓 및 서비스 공개 계획을 유지한다. 장치 사용 승인을 추가로 받은 것으로 간주하지 않는다. 순수 정책의 반복 음절, 조각 소비와 복원, 오답 후 완성 가능성부터 테스트하고 실제 개발 화면에서 한 판 전체를 끝내는 입력 여정을 검수한다.
