## 목적, 범위와 흐름

이미지를 계속 쌓지 않고 실행 중인 이미지와 롤백 수단을 보존한다. 생성 작업이 실행 중인데 공개본 점검이 먼저 실패하거나, 오류 로그가 멎은 상태를 정상 복구로 통지하는 문제를 고친다. 앱 화면과 퍼즐 정책은 이 설계에서 바꾸지 않는다.

| 현재 | 변경 |
|---|---|
| 컨테이너 이미지 14개, 자동 정리 없음 | 실행 및 롤백 보호 태그, 패키지별 최신 2개, 생성 후 14일이 지난 나머지 자동 정리 |
| generator 00:05, 최대 30분, health 00:30 | generator 00:05 유지, health 00:40으로 변경 |
| 오류 로그 집계 종료도 복구 알림 | 오류 발생 알림만 발송. 이 정책의 CLOSED는 정상 복구로 통지하지 않음 |

사용자 화면 변경은 없어 화면 시안과 접근성 변경은 해당하지 않는다. 정상 공개본과 이전 진행 상태를 보존한다.

## 구조와 데이터

설정 정본은 이 저장소의 JSON 정책과 setup 스크립트로 둔다. 기존 Artifact Registry, Scheduler, Monitoring 정책을 갱신하며 새 서비스나 키를 만들지 않는다.

- 프로젝트: crossword-puzzle-79ae0, 리전 asia-northeast3.
- 저장소: crossword-puzzle. 변경 전 전체 이미지, 태그, Cloud Run Job과 서비스의 사용 이미지를 조회해 기록한다.
- 보존 태그: runtime-current, runtime-rollback. 보호 태그와 패키지별 최신 2개 보존은 삭제 규칙보다 우선한다.
- 현재 보호: puzzle-pack-job:79d6a91의 digest 6740fac75b9f0f73088180ca68a8bb7f72939477d70f382443a8937faa41f085.
- 초기 롤백 보호: puzzle-pack-job:9df6c33의 digest b7960140686070901f9ad2fb18e8b12b994a71c8d91bba44070ec522b9a00ff1.
- 위 두 이미지와 completion-stats-job의 최신 2개를 보존하면 현재 후보는 10개다. 삭제 직전 다시 조회해 새 사용처가 있으면 해당 이미지는 제외한다.
- 오래된 latest가 현재 이미지와 다르므로 puzzle-pack-job:latest를 실제 현재 digest에 맞춘다. Job의 실행 digest는 바꾸지 않는다.
- 향후 배포 setup은 이미지 교체 전에 기존 실행 이미지를 롤백으로 보호하고 새 이미지를 보호한다. 두 Job의 이미지가 일치하고 공개본 검사를 통과한 뒤 current를 확정한다. 실패 시 기존 Job과 보호 상태를 보존한다. 보존 태그 수는 두 개로 제한한다.
- cleanup policy는 먼저 미리보기로 저장하고, 실제 이미지 목록에 적용한 삭제 후보를 확인한 뒤 활성화한다. 최초 정리는 검토한 digest만 대상으로 하며 매번 사용 이미지와 보존 조건을 재확인한다.

기존 사용자 퍼즐, Hosting, 정답 이력, 자격증명, 앱 저장 데이터는 삭제 대상이 아니다. 생성 이미지에만 해당한다. 삭제된 과거 빌드를 즉시 되살릴 수는 없으므로 현재와 롤백 이미지의 pull 가능 여부를 먼저 확인한다.

## 알림과 실패 처리

기존 ERROR 로그 metric과 수신 채널을 유지한다. 알림 문구에는 실행 오류와 공개본 점검 실패를 구분하는 확인 방법, 00:40 점검 시각, CLOSED가 복구 검증이 아니라는 점을 적는다. notificationPrompts는 OPENED만 사용한다.

health 00:40은 00:05 시작과 30분 실행 제한 뒤의 최종 점검이다. 생성이 아예 실행되지 않거나 timeout이면 오늘 공개본 부재로 실패해야 한다. 점검이 성공했는지는 실제 PASS 결과로 확인한다. 다음 날 팩 미리 생성은 단일 퍼즐 설계의 rollout에서 따로 다룬다.

## 인수조건과 테스트

| 조건 | 검증 |
|---|---|
| OPS-1 실행 이미지, 롤백, 최신 2개는 삭제 대상이 아님 | 가짜 이미지 목록으로 태그, 나이, 최신 개수, 사용 중 digest 조합 검증 |
| OPS-2 예전 SHA 태그가 붙은 이미지도 정리되며 보호 태그는 남음 | 정책과 후보 계산 단위 검증, 실제 목록 미리보기 |
| OPS-3 배포를 거듭해도 보호 태그가 무한 증가하지 않음 | 연속 배포, 실패 배포의 상태 전이 검증 |
| OPS-4 생성 작업과 경합하지 않는 점검 시각 | setup dry-run, Scheduler live readback |
| OPS-5 복구로 오인할 CLOSED 통지를 보내지 않음 | 생성된 정책 JSON과 실제 alertStrategy readback |
| OPS-6 공개본이 계속 제공됨 | 변경 전후 오늘 공개본 health PASS, 현재 이미지 접근 확인 |

테스트: L1, 개발 환경의 서비스 런타임과 mock GCP 명령, 실제 조회와 읽기 검사. 기기 검수는 변경과 무관하므로 포함하지 않는다. TDD는 삭제 후보와 보호 상태, 생성되는 정책을 대상으로 한다. GCP 보관 크기와 실제 청구 감소는 반영 지연이 있어 즉시 절감 완료로 보고하지 않는다.

## 적용과 복구

설계 승인 후 실행 이슈, 구현, 로컬 리뷰, Ready PR, 필수 검사와 병합을 거쳐 기존 운영에 적용한다. 설정 원본은 비공개 근거 폴더에 기록한다. 실패하면 자동 삭제를 dry-run으로 되돌리고 알림과 스케줄 설정을 원복한다. 현재 또는 롤백 이미지 조회가 안 되면 삭제하지 않는다.

공개 적용 범위는 service만이다. 앱 마켓 배포는 별도 단일 퍼즐 설계 범위다.
