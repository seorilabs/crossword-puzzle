# 타일 화면 구현과 검수 범위

선택한 A 외형과 고정 배치 시안을 실제 Web/AIT와 RN 화면에 반영했다. 홈의 주 행동은 오늘 큰 판 시작 또는 이어 풀기이며, 완료 화면은 실제 완성 판과 기록을 보여 준다. 지난 판은 기록 화면에서 열 수 있다. 첫 실행도 같은 오늘 판에서 쉬운 세 단서를 권한다.

같은 화면에서 보드, 단서, 답칸과 후보 영역의 크기를 유지한다. 후보는 다섯 열과 두 줄을 미리 확보하며 긴 과거 판에서는 후보 영역 안에서만 스크롤한다. 시스템 키보드를 사용하지 않는다. 틀린 단어는 맞은 칸을 보존하고 틀린 칸만 비우며, 직접 선택, 지우기, 힌트와 부분 입력 복원을 공통 core 정책으로 처리한다.

기존 쉬움과 큰 판의 진행을 읽는다. 이전의 맞은 칸과 틀린 칸, 힌트 사용 수를 보존하고 날짜별 공용 힌트 지갑을 한 번만 이관한다. 완성된 저장 판을 여는 동작은 새 완료 이벤트를 만들지 않는다. 첫 세 단어 안내도 기존 진행을 새 안내 완료로 분류하지 않는다.

## 실행 범위

`qa`는 실제 앱 진입점과 어댑터를 실행하며 외부 SDK와 퍼즐 HTTP 응답만 고정 입력으로 대체한다. RN 화면은 React Native Web과 제품의 React 19.2.3으로 렌더한다. 실제 네이티브 렌더러, 광고 서버, 인증, 공유 시트와 OS 알림 권한의 실행 근거와 구분한다. 기기는 사용하지 않았다.

작성자 사전 검수에서 Web과 Android 분기 모두 새 20단어 판의 완주, 부분 저장과 복원, 빈 상태로 지우기, 오답 복구, 전체 단서에서 고정 보드, 공유와 기록, 선택한 알림 안내 수락을 실행했다. 이전 5×5와 큰 판, 힌트 지갑 이관도 실제 화면에서 확인했다. iOS 분기는 작은 화면과 위아래 안전 여백으로 같은 흐름을 확인한다. 글자 확대, 타이머, 광고 보상과 취소, 광고 오류, 저장 오류도 검수 도구에 포함한다.

기존 두 단계 사다리, 입력 방식 전환과 완료 모달의 문구 개수를 검사하던 소스 검사는 제거했다. 새 입력은 core, 실제 컴포넌트, RN App 상태 전환과 브라우저 사용자 여정으로 검증한다. 스토어, SDK와 빌드 계약 검사는 유지한다.

현재 기록은 구현과 사전 검수 범위다. 최종 공개 후보 SHA의 독립 전체 회귀 세 회와 30일 생성 비교, 중앙 출시 검증, 마켓별 공개와 live 확인이 남아 있다. 코드 병합이나 사전 빌드를 공개 완료로 표시하지 않는다.

## 계측과 후속 판단

첫 안내의 `first_three_words_shown`, `first_three_words_complete`, `first_three_words_skip`과 타일 선택은 공통 core 계약이다. 안내 노출은 앱을 다시 열면 재발화할 수 있으므로 퍼즐별 고유 사용자 단위로 비교한다. 전체 완주는 `game_puzzle_complete`로 집계하며 기존 `mission_complete`를 더하지 않는다. `input_policy=syllable-v1`으로 새 입력을 분리한다. 안내를 원격으로 끈 사용자를 안내 완료율의 분모에 섞지 않는다.

새 국가의 콘텐츠나 마켓 등록은 이번 구현에 포함하지 않는다. 입력은 NFC 문자 단위를 사용하며 영어의 반복 글자도 구분한다. 새 언어는 어휘와 단서, 후보의 글자 집합과 문구 길이를 해당 언어로 다시 검수해야 한다. 네이티브의 사운드와 햅틱 어댑터는 기존 구현 범위대로 미지원이며, 새 SDK를 추가하지 않았다.

원본 화면과 실행 JSON, 로그는 최종 검수 후 NAS1dual에 이관하고 직접 읽은 크기와 SHA-256 보관 목록을 연결한다. 현재 경로를 최종 후보 검수 원본으로 재사용하지 않는다.

## 코드 리뷰 후 보완

진행 중인 첫 안내가 다른 미시작 판을 열 때 바뀌는 경우와, 모바일 첫 입력 확인 상태가 메모리에 남지 않는 경우를 회귀 테스트로 재현한 뒤 수정했다. 기존 안내는 원래 판으로 돌아왔을 때 이어지며, 입력한 사용자의 새 판을 첫 안내 단서로 다시 옮기지 않는다. 공개 판이 없는 상태는 준비 문구로 표시하며 미래 판을 시작하지 않는다.

새 안내 이벤트를 집계하는 SQL과 세 마켓 계약 문서를 갱신했다. SQL의 첫 안내와 한 판 완주 분모를 구분하고, 과거 1회 입력 안내와 새 세 단어 안내를 합치지 않는다. 실제 BigQuery 실행은 아직 수행하지 않았다.

보완 뒤 core 696개, 컴포넌트 213개와 모바일 131개 테스트, 타입 검사, 린트와 마켓 계약 검사가 통과했다. 승인한 계획의 인증 및 광고 하한 조정과 v1.2.0 결정은 설계 폴더의 승인 기록을 따른다. 실제 SDK 및 기기 검수는 미실행이다.
