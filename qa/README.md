# 개발 환경 화면 검수

`npm run dev:qa-web`는 실제 웹 앱 진입점과 어댑터를, `npm run dev:qa-native`는 실제 RN 시작 파일 `apps/mobile/index.js`와 App, 어댑터를 브라우저에서 실행한다. AppRegistry를 통해 인증, presence와 업데이트 안내 초기화도 같은 시작 경로로 검수한다. RN은 React Native Web으로 화면만 렌더하며 네이티브 SDK와 OS 동작 검증을 뜻하지 않는다. 실제 광고, 인증, 분석, 알림과 플랫폼 네트워크를 외부 SDK 경계의 고정 입력으로 대체한다. 검수 이벤트는 `window.__crosswordQa.events`에만 모은다.

웹은 4183, RN은 4182 포트를 사용한다. `?run=<고유 검수명>`으로 저장 공간을 격리하며 RN은 `platform=android` 또는 `platform=ios`로 플랫폼 분기도 실행한다. 소스는 같은 앱을 사용하며 별도 모형 화면을 만들지 않는다. 퍼즐 응답은 실행 도구가 `qa/fixtures` 데이터로 대체하고, 신규와 기존 진행 상태를 각각 독립한 실행명으로 확인한다.

RN 검수는 `apps/mobile`에 설치된 실제 제품과 같은 React 19.2.3과 검수용 React DOM 19.2.3을 사용한다. 웹 제품의 React 18과 의존성을 섞지 않는다. React Native Web은 DOM 렌더링 경계이며 실제 네이티브 렌더러의 실행 근거가 아니다.

`window.__crosswordQa`에서 광고 보상, 중도 닫기와 오류, 원격 설정 실패, 인증 실패와 저장 실패를 설정한다. 실제 서비스와 기기를 호출하지 않는다. 고정 입력의 성공은 SDK의 실제 성공으로 기록하지 않는다.

이미지와 실행 원본은 소스 밖에서 수집하고 검증 후 NAS1dual로 이관한다. Git에는 실행 코드와 필요한 고정 입력만 보관한다.

`offline_resume.py`는 글자와 힌트를 사용한 실제 풀이 화면에서 연결 실패와 새로고침을 재현한다. 불러오지 못한 기본 판을 표시하지 않고 재시도한 뒤 같은 퍼즐의 글자, 확정 칸과 일일 힌트 잔액을 복원하는지 확인한다. 결과는 별도 출력 폴더에 저장하며 실행 이름으로 데이터를 격리한다.

## 연속 플레이 검수

`continuous_journey.py`는 오늘 5판에서 최근 지난 판으로 이어지는 실제 타일 입력을 검수한다. 원본 보드의 ID, 날짜, 단서와 정답을 유지하고 HTTP와 외부 SDK 경계만 격리한다. `run_chain`은 홈에서 보드 원본을 내려받지 않는지, 부분 입력과 재실행 복원, 오답 복구, 다음 판 이동과 결과의 주 행동이 화면 안에서 보이고 키보드로 선택되는지 확인한다. `run_seeded_selection`은 완료, 도전 소진, 진행 중인 판과 빈 상태를 재현할 때 쓴다.

`completed_values`와 `ad_history`는 격리된 저장 상태 입력이다. `with_history_fixture`가 만드는 35개 과거 판은 실제 생성 보드를 복제하고 검수용 날짜와 ID를 부여한 상태 검사 자료다. 이를 새로운 실제 공급이나 실제 광고 노출로 세지 않는다.

`ContentBoundary`는 manifest와 선택 보드의 HTTP 요청 수, 제공한 JSON 본문의 UTF-8 바이트와 SHA-256을 기록한다. 비교할 때 같은 보드, 언어, 실행 환경과 사용자 행동을 고정한다. JSON 본문 크기는 헤더, 압축과 TLS를 포함한 실제 전송량이나 과금 내역과 구분한다. 기준 버전의 비용 측정은 새 후보의 독립 화면 검수 회차로 세지 않는다.

정식 회차는 최종 후보 SHA가 정해진 뒤 실행 전에 계획을 기록한다. 각 회차의 원래 판정과 실행 시각을 보존하며 화면을 직접 보고 기능과 UX를 따로 판정한다. 종전 `bilingual_journey.run_daily`의 다섯 판 뒤 홈 이동 기대와 `offline_resume.py`의 힌트 지갑 기대는 과거 정책용이므로 이번 연속 플레이 검수에는 적용하지 않는다.
